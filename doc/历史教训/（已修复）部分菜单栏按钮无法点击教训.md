# Bug复盘：部分菜单栏按钮无法点击

## 1. 现象

- 部分情况下，菜单栏的"文件"、"编辑"按钮无法点击（无悬停提示、无点击响应）
- 如果"编辑"无法点击，则"文件"一定无法点击
- 是否可点击随窗口移动而变化

## 2. 根因

### 2.1 直接原因

`EditorTabWidget`（TabWidget）在从布局中取出 tabBar 和 stackedWidget 后，自身仍作为可见控件存在于 `editor_interface` 中，其 `pos=(0,0)` 覆盖了菜单栏的左上角区域。

`QApplication.widgetAt()` 在菜单按钮位置返回 `EditorTabWidget` 而非按钮本身，导致 Qt 事件系统将鼠标事件派发给 TabWidget 而非菜单按钮。

### 2.2 根本原因

原布局代码：

```python
self._tab_widget = EditorTabWidget(self._editor_interface)

# 从TabWidget内部取出tabBar，放到editor_interface顶层布局
self._tab_widget.vBoxLayout.removeWidget(self._tab_widget.tabBar)
layout.addWidget(self._tab_widget.tabBar)

# stackedWidget放入splitter
self._splitter.addWidget(self._tab_widget.stackedWidget)
layout.addWidget(self._main_splitter, 1)
```

问题链条：

1. `EditorTabWidget` 创建时 parent 为 `editor_interface`，被 Qt 对象树管理
2. tabBar 从 TabWidget 的 vBoxLayout 取出，但 **TabWidget 本身仍在 editor_interface 中**（虽然不在布局中，但作为子控件存在）
3. stackedWidget 被放入 splitter，TabWidget 内部只剩空壳
4. TabWidget 的 sizeHint 缩小为极小值（100x30），`pos=(0,0)` 从 editor_interface 左上角开始
5. 该极小矩形覆盖了菜单栏左侧按钮的区域（文件、编辑在左，视图等在右）
6. Qt 的 `widgetAt()` 从子控件向上查找时，优先找到 TabWidget，而非菜单按钮
7. 结果：文件、编辑按钮被遮挡，视图等右侧按钮正常

### 2.3 为什么随窗口移动变化

`widgetAt()` 基于屏幕全局坐标查找。TabWidget 的全局位置随窗口移动而变化，而其 100x30 的矩形覆盖区域也随之移动。当窗口位置恰好使 TabWidget 矩形不覆盖菜单按钮时，按钮可正常点击。

## 3. 修复方案

```python
self._tab_widget = EditorTabWidget(self._editor_interface)

# 取出tabBar，重新设置parent为editor_interface
self._tab_widget.vBoxLayout.removeWidget(self._tab_widget.tabBar)
self._tab_widget.tabBar.setParent(self._editor_interface)
layout.addWidget(self._tab_widget.tabBar)
self._tab_widget.vBoxLayout.setContentsMargins(0, 0, 0, 0)

# 关键修复：TabWidget取出子控件后成为空壳，需要禁用其鼠标事件并隐藏
self._tab_widget.setAttribute(Qt.WA_TransparentForMouseEvents)
self._tab_widget.hide()
```

两行修复：
- `setAttribute(Qt.WA_TransparentForMouseEvents)`：让鼠标事件穿透 TabWidget，不被其拦截
- `hide()`：让 TabWidget 不参与绘制和布局，彻底消除遮挡

## 4. 正确的子控件取出布局模式

当需要从容器控件中取出子控件放到外部布局时，必须处理容器空壳：

```
原容器（取出子控件后成为空壳）
├── 子控件A（已取出到外部布局）
└── 子控件B（已取出到外部布局）

问题：原容器仍在父控件中，pos=(0,0) 覆盖其他控件

修复方式：
  方式1：设置 WA_TransparentForMouseEvents + hide()（本方案）
  方式2：将原容器从父控件的布局中移除
  方式3：不取出子控件，改为调整原容器的布局边距
```

### 4.1 取出子控件的标准步骤

1. 从原容器布局中移除子控件：`layout.removeWidget(child)`
2. 重新设置子控件的 parent：`child.setParent(new_parent)`
3. 将子控件添加到目标布局：`target_layout.addWidget(child)`
4. **处理原容器空壳**：若原容器不再需要可见，设置 `setAttribute(Qt.WA_TransparentForMouseEvents)` 和 `hide()`

### 4.2 Qt布局中widgetAt遮挡的通用排查方法

1. 用 `QApplication.widgetAt(globalPos)` 检查光标下实际命中的控件
2. 若命中控件非预期，检查该控件的 `pos()`、`geometry()`、`mapToGlobal()` 判断其覆盖区域
3. 常见遮挡源：空壳容器控件、z-order更高的同级控件、透明但接收事件的覆盖层

## 5. 教训

- **取出子控件后必须处理空壳容器**：Qt的对象树不会自动移除无子控件的容器，它仍占据空间和接收事件
- **pos=(0,0) 是高危信号**：任何 pos=(0,0) 的可见控件都可能遮挡同级兄弟控件
- **布局调试优先看 widgetAt**：点击无响应时，第一步应该是检查 `widgetAt()` 返回什么，而非追踪信号连接
