# 语法高亮器与分屏系统重构方案

## 一、语法高亮器问题分析

### 问题 1：高亮器生命周期管理分散（严重）
高亮器的创建、配色应用、主题更新逻辑在四处重复：
| 位置 | 内容 |
|------|------|
| `tab_manager.py:163-178` | `create_tab()` 中创建高亮器+应用配色 |
| `tab_manager.py:414-435` | `mark_saved()` 中根据扩展名重建高亮器 |
| `tab_manager.py:602-614` | `set_editor_colors()` 中遍历全部高亮器更新配色 |
| `syntax_helper.py:36-88` | `apply_language_to_tab()` 中重建高亮器+应用配色 |

**后果**：修改状态同步逻辑散落四处，高亮器在 `mark_saved` 重建后可能丢失主题配色（`theme_service.py:327-359` 定义的 `syntax_colors` 子字典未正确传递）。

### 问题 2：`create_highlighter` 工厂函数缺陷（`syntax_highlighter.py:393-435`）
```python
# 第 418-431 行
lang_key = language.lower()
lexer_alias = _LEXER_ALIAS_MAP.get(lang_key, lang_key)  # 永不返回 None！
# ...
if lexer_alias is None:  # 死代码！此条件永远不成立
    return PlainHighlighter(parent)
```
当 `language="plain"` 时，`get_lexer_by_name("plain")` 会抛出异常，触发 `except` 分支返回 `PlainHighlighter`。功能正确，但逻辑绕道，且死代码存在。

### 问题 3：高亮器与分屏编辑器完全脱节（严重）
`SplitViewManager.open_split_view()`（`split_view_manager.py:136-138`）创建新的 `CodeEditor` 时：
```python
self._split_editor = CodeEditor()
self._split_editor.setPlainText(editor.toPlainText())
```
- **没有高亮器**：未调用 `create_highlighter()` 创建任何高亮器
- **没有编辑器配色**：未调用 `set_editor_colors()` 设置主题
- **没有信号绑定**：未调用 `_bind_editor_signals()` 连接 `text_modified` / `cursor_position_changed` / `zoom_changed` 信号
- 因此修改标记、光标同步、搜索、缩放、主题切换等功能在分屏中均失效

### 问题 4：`syntax_helper.py:59-67` 违反分层
```python
current_colors = getattr(tab_manager, '_current_editor_colors', None)
```
`syntax_helper`（UI 层辅助模块）直接访问 `TabManager`（Controller 层）的私有属性，违反 `UI→Controller→Service→Infrastructure` 的分层约束。

### 问题 5：高亮器多行 Token 状态未追踪
`PygmentsHighlighter.highlightBlock()`（`syntax_highlighter.py:386`）始终设置 `setCurrentBlockState(0)`，不追踪多行 Token 的跨行状态。对于 Python 三引号字符串、C 多行注释等，多行高亮会中断。

## 二、分屏系统问题分析

### 问题 6：Controller 层通过 `self.parent()` 反向依赖 UI 层（严重）
`TabManager.get_current_editor()`（`tab_manager.py:264-273`）：
```python
mw = self.parent()
if (mw is not None and hasattr(mw, '_split_active') and mw._split_active
    and hasattr(mw, '_focus_side') and mw._focus_side == 1
    and hasattr(mw, '_split_editor') and mw._split_editor is not None):
    return mw._split_editor
```
这是严重的架构违反 —— Controller 层通过 `parent()` 向上回溯并访问 UI 层对象（`_split_editor`）的私有属性。同样的问题在 `get_current_file_path()`（`tab_manager.py:284-295`）中也有。

### 问题 7：SplitViewManager 职责模糊
`SplitViewManager` 目前混合了三层职责：
- **UI 层**：创建/销毁 `CodeEditor`、管理 `QSplitter`
- **Controller 层**：分屏状态管理、焦点切换
- **数据同步**：从主编辑器复制文本

### 问题 8：分屏编辑器没有语法高亮
如问题 3 所述，创建分屏编辑器时不走 `TabManager.create_tab()` 流程，跳过高亮器创建和配色应用。

### 问题 9：主题切换不更新分屏编辑器
`MainWindow._on_theme_changed_apply()`（`main_window.py:868`）调用 `self._tab_manager.set_editor_colors(editor_colors)`，该方法仅遍历 `TabWidget` 中的编辑器，不会更新 `SplitViewManager` 持有的 `_split_editor`。

### 问题 10：搜索/配置更新不作用于分屏编辑器
`_on_search_execute`（`main_window.py:1313`）、`_on_config_updated`（`main_window.py:1246`）等方法均使用 `self._tab_widget.current_editor()`，当焦点在分屏时不会操作分屏编辑器。

### 问题 11：分屏状态不持久化
分屏的激活状态、方向、分隔条比例未保存到 `session.json`，重启后丢失。

### 问题 12：空槽函数引入困惑
`ActionManager._on_split_vertical()` 和 `_on_split_horizontal()`（`action_manager.py:631-642`）是空实现，通过 `_override_action` 在 `MainWindow` 中替换。这种间接机制不直观，容易让后续开发者混淆。

### 问题 13：分屏事件过滤器耦合
`MainWindow` 作为 `eventFilter` 附加到分屏编辑器 viewport 上，焦点检测依赖 `obj is svm.split_editor.viewport()` 的引用比较（`main_window.py:1743`），脆弱且不灵活。

### 问题 14：`_syncing_tab` 递归防护脆弱
`SplitViewManager._syncing_tab` 的防递归机制（`main_window.py:652-654`）依赖 flag 的及时复位，缺少异常保护容易死锁。

## 三、重构方案

### 3.1 高亮器重构

**目标**：抽取高亮器管理的公共职责到 `SyntaxHighlighterManager`（Service 层），作为高亮器生命周期的单一权威。

**步骤**：

#### 3.1.1 新建 `SyntaxHighlighterManager`
```
src/service/syntax_highlighter_manager.py
```

职责：
- 创建高亮器（委托 `create_highlighter` 工厂）
- 管理高亮器 ↔ 文档的映射关系
- 统一更新配色到所有活跃高亮器
- 提供 `apply_to_editor(language, editor, file_size, colors)` 单一入口

#### 3.1.2 重构 `tab_manager.py`
- 注入 `SyntaxHighlighterManager` 替代 `highlighter_factory`
- `create_tab()` 通过 `SyntaxHighlighterManager.apply_to_editor()` 创建高亮器
- `mark_saved()` 通过同一方法重建高亮器（消除第 414-435 行重复代码）
- `set_editor_colors()` 委托 `SyntaxHighlighterManager.update_all_colors()`
- 删除 `syntax_helper.py` 模块（其逻辑合并到 Manager 中）

#### 3.1.3 修复 `create_highlighter` 工厂函数
- 删除 `syntax_highlighter.py:422-424` 的死代码
- 为 `PlainHighlighter` 添加明确的空语言/纯文本路径

#### 3.1.4 修复多行 Token 状态
- 修改 `PygmentsHighlighter.highlightBlock()` 以追踪 `setCurrentBlockState`，处理跨行词法单元（Python 三引号字符串、多行注释等）

### 3.2 分屏系统重构

**目标**：
1. 消除 Controller → UI 的反向依赖
2. 分屏编辑器获得与主编辑器一致的能力
3. 清晰划分 SplitViewManager 的职责

#### 3.2.1 消除 `TabManager` 中的 `self.parent()` 反依赖（核心问题）

**方案 A（推荐）**：引入 `FocusManager`（Controller 层新模块）

```
src/controller/focus_manager.py
```

`FocusManager` 负责：
- 维护当前活跃编辑器引用（`_active_editor: CodeEditor | None`）
- 维护焦点侧状态（`_focus_side: int`）
- 维护分屏编辑器引用（由 `SplitViewManager` 设置）
- 提供 `get_active_editor()` / `get_active_file_path()` 等方法

**变更**：
- `TabManager.get_current_editor()` → 重命名为 `get_tab_editor(index: int)`，仅返回标签对应的编辑器
- `TabManager.get_current_file_path()` → 类似重命名
- 所有需要"当前活跃编辑器"的位置改为调用 `FocusManager.get_active_editor()`
- `ActionManager` / `MainWindow` 使用 `FocusManager` 替代 `TabManager.get_current_editor()`

#### 3.2.2 重构 SplitViewManager

职责重新划分：
- **UI 层**（保留在 `split_view_manager.py`）：QSplitter 管理、分屏创建/销毁、尺寸调整
- **Controller 层**（迁移到 `FocusManager`）：焦点追踪、编辑器引用管理

新增接口：
```python
class SplitViewManager:
    def open_split(self, orientation: int) -> None
    def close_split(self) -> None
    def is_split_active(self) -> bool
    def get_split_editor(self) -> CodeEditor | None
    def split_editor_ready(self, editor: CodeEditor) -> None  # 初始化完成回调
```

#### 3.2.3 分屏编辑器初始化完整化

在 `SplitViewManager.open_split_view()` 创建 `CodeEditor` 后：
1. 通过 `SyntaxHighlighterManager.apply_to_editor()` 设置高亮器
2. 调用 `set_editor_colors()` 应用当前主题
3. 调用 `_bind_editor_signals()` 绑定信号
4. 注册到 `FocusManager`
5. 应用当前配置（行号、自动换行、字体等）

#### 3.2.4 修复主题/配置/搜索作用范围

- `_on_theme_changed_apply`：通过 `FocusManager` 获取所有活跃编辑器（含分屏）更新
- `_on_config_updated`：同理
- 搜索操作：通过 `FocusManager.get_active_editor()` 获取当前编辑器

#### 3.2.5 分屏状态持久化

在 `session.json` 中添加字段：
```json
{
  "split_active": true,
  "split_orientation": 1,
  "split_sizes": [300, 300]
}
```
`TabManager.save_full_session()` 保存，`_restore_session()` 恢复。

#### 3.2.6 清理空槽 + `_override_action` 机制

- 删除 `ActionManager._on_split_vertical/horizontal` 空实现
- 直接在 `MainWindow.connect_signals()` 中将 split 动作连接到内部槽
- 删除 `_override_action()` 方法

#### 3.2.7 用 `QPointer` 替代 `eventFilter` 的引用比较

但鉴于 PyQt5 没有 `QPointer`，可改用基于 `objectName` 或显式接口的方法：
```python
# 在 SplitViewManager 中添加：
def is_split_viewport(self, viewport) -> bool
```
