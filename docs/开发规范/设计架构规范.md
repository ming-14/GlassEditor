# 设计架构规范

## 1. 架构哲学

**根本目标**: 确保长期可维护性，防止功能堆叠导致"七零八落、不断打补丁"。

**核心原则**:

| 原则 | 说明 | 违反代价 |
|------|------|----------|
| **严格分层** | 依赖方向唯一：UI→Controller→Service→Infrastructure，禁止逆向 | 循环依赖、测试困难 |
| **单向数据流** | 变更通过 SignalBus 向下广播，修改通过 Service 层向上回传 | 状态不一致 |
| **依赖注入** | 模块间通过构造器注入，禁止内部 `import` 跨层模块实例 | 紧耦合 |
| **单一职责** | 每个模块、类、函数只有一个明确的职责 | 代码膨胀 |
| **显式优于隐式** | 数据流、状态变更、异常路径必须显式表达 | 难以追踪的 Bug |
| **一致性强于性能** | 架构一致性面前微性能优化可妥协（热点路径除外） | 架构侵蚀 |

**禁止行为**：❌ 为快速实现功能临时跨越层调用 ❌ UI 层直接读写文件或配置 ❌ Infrastructure 引用任何上层模块 ❌ Service 直接 import UI 组件 ❌ `__init__.py` 中批量暴露内部实现

**必须行为**：✅ 新功能遵循分层结构 ✅ 跨层通信通过 SignalBus 或依赖注入 ✅ 提交前检查分层依赖 ✅ 功能修改同步更新文档

### 2.1 层间通信契约

| 方向 | 方式 | 示例 | 规则 |
|------|------|------|------|
| UI→Controller | Qt 信号连接 | `button.clicked.connect(mgr.new_file)` | UI 仅发射 Qt 信号，目标必须是 Controller 公共槽 |
| Controller→Service | 方法调用+(result,error) | `content, err = svc.open_file(path)` | Controller 持有 Service 引用（构造器注入） |
| Service→Infrastructure | 方法调用 | `settings.get("font_size", 13)` | Infrastructure 方法设计为纯函数或状态明确的类方法，不感知业务语义 |
| 跨层广播 | SignalBus(pyqtSignal) | `signal_bus.file_opened.emit(path)` | 用于 1:N 广播；确定的 1:1 通信用直接信号 |

### 2.2 依赖注入方式

- **构造器注入（优先）**：`def __init__(self, file_service, theme_service, ...)`
- **属性注入（可选依赖）**：`coordinator.config_service = config_service`
- **工厂方法注入（延迟创建）**：`editor_factory: Callable[[], CodeEditor]`
- **类型注解**：跨层使用 `TYPE_CHECKING` 避免循环导入

```python
# ✅ 正确
if TYPE_CHECKING:
    from src.service.file_service import FileService
class ActionManager(QObject):
    def __init__(self, file_service: "FileService"):
        self._file_service = file_service  # 接收已创建实例

# ❌ 禁止：模块内部 import 并实例化跨层对象
from src.service.file_service import FileService
self._file_service = FileService()  # 禁止！
```

## 3. 模块职责

### 3.1 Infrastructure 层

| 模块 | 职责 | 约束 |
|------|------|------|
| `singleton.py` | 提供 Singleton/QSingleton 元类 | 所有单例统一使用，禁止自行实现 |
| `settings.py` | JSON 配置读写、500ms 去抖、原子写入 | 线程安全 RLock |
| `logger.py` | Loguru 日志配置 | 遵循独立日志规范 |
| `file_io.py` | 底层文件读写、原子写入 | atomicwrites，不包含业务语义 |
| `encoding_detector.py` | BOM+chardet 检测 | 置信度≥0.5，否则回退 UTF-8 |
| `encoding_utils.py` | 编码菜单分组、显示名称映射、编码转换核心逻辑 | 纯函数，不依赖 Qt |
| `shortcut_registry.py` | 快捷键持久化+冲突检测 | 基于逆向索引表 |
| `app_constants.py` | 数值常量集中管理 | AppConstant 类，禁止魔法数字 |
| `config_keys.py` | 配置键名字符串集中管理 | ConfigKey 类，禁止魔法字符串 |
| `cli_args.py` | CLI 参数解析 | ParsedArgs 数据类 |

### 3.2 Service 层

| 模块 | 职责 | 状态 |
|------|------|------|
| `file_service.py` | 文件打开/保存/重载、编码检测/转换、行尾检测、最近文件列表 | 无状态（列表存于 settings.json） |
| `search_service.py` | 查找替换正则逻辑、搜索结果管理 | 有状态（匹配列表/当前索引/选项） |
| `theme_service.py` | 颜色方案管理（暗/亮/高对比）、Fluent 主题切换、编辑器配色构建 | 有状态（当前主题索引、色板字典），QSingleton |
| `config_service.py` | 配置 pydantic 校验+包装、默认值合并、会话保存/加载 | 无状态（委托给 Settings 读写+去抖，自身不管理写入定时器） |
| `syntax_service.py` | 扩展名→语言映射（约30种语言） | 无状态（静态映射表） |
| `tool_service.py` | 文本统计、哈希计算、排序去重、大小写转换 | 无状态（纯函数） |
| `dialog_coordinator.py` | 对话框延迟创建、消息展示、文件对话框 | 无状态（仅协调） |
| `syntax_highlighter_manager.py` | 高亮器生命周期管理：创建/配色更新/语言切换 | 无状态（不持有编辑器/高亮器引用，引用由 TabManager tabData 管理） |

### 3.3 Controller 层

| 模块 | 职责 | 约束 |
|------|------|------|
| `signal_bus.py` | 全局信号总线单例 | 信号数量≤20 个，避免信号泛滥 |
| `action_manager.py` | 动作注册、快捷键管理、所有槽函数 | 每槽函数必须有 try-except |
| `tab_manager.py` | 标签创建/关闭/切换、文件监听、会话自动保存、编码转换 | 元数据存于 tabData()，不维护独立列表 |
| `focus_manager.py` | 焦点侧状态、分屏编辑器引用、各屏标签页索引管理 | 分屏引用由 SplitViewManager 设置/清除，FocusManager 仅持有 |

### 3.4 UI 层

| 模块 | 职责 | 约束 |
|------|------|------|
| `main_window.py` | 主窗口布局、命令栏、信号编排、会话恢复、插件初始化 | 编排器(Orchestrator)，不包含业务逻辑（当前约2000行，已将菜单栏/欢迎页/分屏/搜索结果面板拆分为独立组件） |
| `code_editor.py` | 编辑器、行号槽、括号匹配、多光标、语法高亮 | ≤2000 行 |
| `editor_tab_widget.py` | 标签容器（含欢迎页）、拖拽排序、stackedWidget 管理 | 封装所有 TabWidget 定制 |
| `search_bar.py` | 内联搜索栏 | 150ms 搜索延迟，与 SearchService 无直接耦合 |
| `status_bar.py` | 状态栏：光标、编码、行尾、语言、缩放 | 编码可点击弹出菜单 |
| `syntax_highlighter.py` | Pygments 语法高亮、高亮器工厂函数 create_highlighter | >5MB 降级 PlainHighlighter |
| `welcome_page.py` | 欢迎页：标题、快捷键速查、主题按钮、新建/打开按钮 | 信号驱动，无业务逻辑 |
| `menu_manager.py` | 菜单栏管理：文件/编辑/视图/语法/工具/帮助菜单 | 信号驱动，不直接执行业务 |
| `search_result_panel.py` | 多文件搜索结果面板：搜索输入、结果树、导航 | 仅负责展示，搜索逻辑委托 SearchService |
| `split_view_manager.py` | 分屏创建/关闭、QSplitter 管理 | 编辑器初始化通过回调由 MainWindow 完成 |
| `dialogs/*.py` | 各功能对话框 | 通过信号发出操作 |

### 3.5 禁止依赖矩阵

| 依赖方\被依赖方 | UI | Controller | Service | Infrastructure |
|:---|---:|:---:|:---:|:---:|
| UI | N | Y | Y* | Y |
| Controller | N | N | Y | Y |
| Service | N | N | N | Y |
| Infrastructure | N | N | N | N |

Y=允许，N=禁止，Y*=UI仅通过信号/回调与 Service 通信

## 4. 设计模式

### 4.1 单例

```python
# ✅ 统一使用元类
from src.infrastructure.singleton import Singleton, QSingleton
class Settings(metaclass=Singleton): ...       # 普通类
class SignalBus(QObject, metaclass=QSingleton): ...  # QObject 子类
# ❌ 禁止自行实现 __new__+_instance
```

| 类 | 元类 | 初始化 | 说明 |
|------|------|--------|------|
| SignalBus | QSingleton | 首次引用时 | 全局信号总线 |
| ThemeService | QSingleton | 首次引用时 | 颜色方案 + Fluent 主题 |
| Settings | Singleton | 首次引用时 | JSON 配置读写 + 去抖写入 |
| ShortcutRegistry | Singleton | 首次引用时 | 快捷键注册表 |

### 4.2 SignalBus

- 信号命名：过去分词 snake_case（`file_opened`, `theme_changed`）
- 参数：第一个参数为事件主体标识符，避免传递 Qt 对象引用
- 使用 SignalBus 的场景：发射方不确定接收方数量、接收方动态增减、全局广播
- 使用直接信号的场景：确定的 1:1 通信、双方同层、需要同步返回值
- **已定义信号（8 个）**：
  - `file_opened(str)` — FileService 发射，path
  - `file_saved(str)` — FileService 发射，path
  - `file_closed(str)` — TabManager 转发，path（注：原始信号由 FileService 在 open_file/save_file 时发射；close_tab 由 TabManager 通过 SignalBus 转发）
  - `file_encoding_changed(str, str)` — TabManager 发射，(path, new_encoding)
  - `theme_changed(str)` — ThemeService.apply_theme() 发射，theme_name
  - `config_updated()` — ConfigService.set() 发射，无参数
  - `status_message(str, int)` — 各模块按需发射，(text, duration_ms)
  - `search_requested(str)` — ActionManager._on_find() 发射，search_text

**TabManager 自有信号**（非 SignalBus，直接连接）：
  - `tab_created(int)` — 标签创建后，参数为标签索引
  - `tab_closed(int)` — 标签关闭后，参数为标签索引
  - `tab_switched(int)` — 标签切换后，参数为新标签索引
  - `file_externally_modified(str)` — 文件被外部修改，参数为文件路径

### 4.3 工厂模式

用于延迟创建复杂对象（DialogCoordinator 的对话框工厂：`importlib.import_module()` 运行时导入）和依赖注入不可直接 import 的对象（TabManager 的编辑器工厂：可调用对象传入）。

### 4.4 观察者模式

一个信号对应一个明确事件语义，槽函数执行时间不超过 50ms（超过需异步），跨线程使用 `Qt.QueuedConnection`。

## 5. 错误处理

**分层策略**：

| 层 | 策略 |
|---|---|
| UI | 捕获 Controller 返回值错误，展示中文友好消息，详细日志 |
| Controller | 每槽函数 try-except，异常→错误字符串返回，ERROR 日志，不因异常崩溃 |
| Service | (result, error) 元组返回；致命异常(配置损坏)允许抛出由 Controller 捕获 |
| Infrastructure | IOError/JSONDecodeError 允许向上传递，添加 context 后重抛，ERROR/CRITICAL 日志 |

**返回值约定**：```def open_file(self, path) -> tuple[str|None, str|None]```

**防御性检查清单**：
- 文件 IO：存在性/权限/大小检查
- 编辑器：`editor is None` 保护
- 标签：`index >= 0` 检查
- 配置：键存在性/类型校验/默认值回退
- 搜索：空搜索词保护、正则有效性检查
- 信号：不传 None 作为必选参数
- 回调：检查是否为 None

## 6. 并发模型

- **主线程**（Qt GUI Thread）：所有 UI 操作、信号发射、<50ms 任务
- **工作线程**：大文件加载(>10MB，后台读取→信号通知)、多文件搜索(每文件子任务)、哈希计算
- **线程安全约定**：Settings 用 RLock 保护读写，Loguru Sink 用 enqueue=True 异步写入，QObject 子类不在非主线程中创建

## 7. 配置分层

| 类型 | 存储 | 内容 | 读写 | 保存时机 |
|------|------|------|------|----------|
| 用户配置 | `%APPDATA%/GlassEditor/settings.json` | 字体/主题/编辑器选项 | Settings(Singleton, RLock) + ConfigService(pydantic 校验) | 500ms 去抖(Settings._DEBOUNCE_MS) |
| 会话状态 | `session.json` | 标签列表/光标位置/编码/语言 | TabManager 每30s调用 ConfigService.save_session() | 30s 自动+退出时 |
| 快捷键 | `shortcuts.json` | 与默认值不同的快捷键集合 | ShortcutRegistry(Singleton) | 快捷键变更时 |
| 运行时状态 | `tabData()`+Service实例变量 | 编辑器引用/搜索状态/修改标记/高亮器引用 | 内存 | 随进程销毁 |

**键名规范**：ConfigKey 类集中管理，snake_case，布尔值用 `show_` 前缀（如 `show_line_numbers`），禁止模块中直接使用字符串字面量。

## 9. 代码组织

**文件内顺序**：模块文档字符串 → import(标准库→第三方→内部) → TYPE_CHECKING → 常量 → 公开类 → 私有类 → 函数

**类内顺序**：类变量 → 特殊方法(`__init__`, `__repr__`) → property → 公开方法 → 信号处理器(`_on_`前缀) → 私有方法 → 静态/类方法

**格式**：缩进 4 空格（禁止 Tab），行宽 100 字符，顶级定义间 2 空行，方法间 1 空行，import 块间 1 空行，文件末尾 1 空行。
