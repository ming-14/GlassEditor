# 信息架构文档

## 1. 架构目标

1. **单源真理**：每份数据只有一个权威来源，消除重复状态和冗余存储
2. **可预测数据流**：变更路径清晰可追踪，读写方向遵循分层约束
3. **崩溃恢复**：会话状态定期持久化，文件写入使用原子操作
4. **隐私保护**：敏感数据脱敏存储，不收集用户隐私信息

### 数据分类体系

| 分类 | 生命周期 | 存储 | 示例 |
|------|---------|------|------|
| transient | 随进程消失 | 内存变量 | 搜索状态、撤销栈、光标位置、对话框状态 |
| session | 下次启动恢复 | session.json + 内存 | 标签页列表、窗口位置、光标快照、分屏布局 |
| persistent | 永久保留 | settings.json | 主题偏好、快捷键设置、编辑器选项、最近文件列表 |

| 敏感度 | 处理方式 | 示例 |
|--------|---------|------|
| public | 正常存储 | 文件内容、编辑器配置、主题颜色 |
| internal | 日志脱敏（路径去除用户名部分） | 文件路径、工作目录 |
| sensitive | 禁止持久化到日志，使用后清除 | 搜索历史、剪贴板内容 |

## 2. 数据实体

### 2.1 核心实体关系

```
Application 1──N Session(标签列表/窗口/光标快照)
    │
    ▼
Tab(路径/编码/行尾/修改标记/只读/语言) 1──N Editor(文本/光标/撤销栈/滚动/高亮)
    │
    0..1
    ▼
File(路径/大小/编码/行尾)          Config(用户设置/快捷键/会话)
```

### 2.2 TabMeta（标签元数据）

**存储位置**：`QTabWidget.tabData()`（随标签自动维护的普通 dict，禁止外部维护独立列表）

当前实现使用普通 dict，非 dataclass。键名如下：

```python
# 实际存储结构（普通 dict，非 dataclass）
tab_meta = {
    "file_path": str | None,     # None=未命名文件
    "encoding": str,             # 如 "utf-8"、"gbk"（默认 "utf-8"）
    "modified": bool,            # 是否有未保存修改
    "file_size": int,            # 文件字节大小（新建文件为 0）
    "language": str,             # 语言类型（如 "Python"），空字符串=纯文本
    "highlighter": QSyntaxHighlighter,  # 语法高亮器实例引用
    "syntax_auto_detect": bool,  # 是否启用自动识别语法（默认 True）
}
```

**注意**：`line_ending`（行尾）、`is_readonly`（只读）、`cursor_line/column`（光标位置）等字段**不**持久化在 tabData 中——行尾和只读由编辑器状态或运行时检测决定；光标位置仅在会话保存时临时读取，不长期存储。

**修改标记同步机制**：编辑器文档的 `isModified()` 通过 `modificationChanged` 信号驱动元数据 `["modified"]` 更新；`mark_saved()` 同时重置文档和元数据，保证二者一致。

### 2.3 SearchState（搜索状态）

**管理方**：SearchService，单源真理（消除 MainWindow 和 ActionManager 间的重复状态）

当前实现使用 SearchService 实例变量，非 dataclass：

| 变量 | 类型 | 说明 |
|------|------|------|
| `_matches` | `List[Tuple[int, int]]` | 匹配位置列表 [(start, end)] |
| `_current_idx` | int | 当前匹配索引（-1 表示无选中） |
| `_last_text` | str | 上次搜索文本，用于缓存判断 |
| `_last_options` | Dict[str, bool] | 上次搜索选项，用于缓存判断 |

**核心方法**：
- `needs_research(text, options)` → bool：比较新参数与 `_last_text`/`_last_options`，参数未变时返回 False 跳过重复搜索
- `advance_next()` / `advance_prev()` → Optional[Tuple]：循环导航到下/上一个匹配
- `find_all(text, content, options)` → (matches, error)：执行搜索并更新状态
- `replace_all(text, replace_text, content, options)` → (count, new_content, error)

### 2.3 SearchState

**管理方**：SearchService，单源真理（消除 MainWindow 和 ActionManager 间的重复状态）

当前实现使用 SearchService 实例变量（非 dataclass，无独立 SearchState 类）：

| 变量 | 类型 | 说明 | 公开 property |
|------|------|------|---------------|
| `_matches` | `List[Tuple[int, int]]` | 匹配位置列表 [(start, end)] | `matches` |
| `_current_idx` | int | 当前匹配索引（-1 表示无选中） | `current_idx` |
| `_last_text` | str | 上次搜索文本，用于缓存判断 | `last_text` |
| `_last_options` | Dict[str, bool] | 上次搜索选项，用于缓存判断 | `last_options` |

**核心方法**：
- `needs_research(text, options)` → bool：比较新参数与 `_last_text`/`_last_options`，参数未变时返回 False 跳过重复搜索
- `advance_next()` / `advance_prev()` → Optional[Tuple]：循环导航到下/上一个匹配
- `find_all(text, content, options)` → (matches, error)：执行搜索并更新状态
- `replace_all(text, replace_text, content, options)` → (count, new_content, error)
- `build_pattern(text, options)` → str：根据搜索选项构建正则模式字符串
- `compile_pattern(pattern_str, case_sensitive)` → Optional[Pattern]：编译正则模式

### 2.4 会话快照（Session）

**存储位置**：`session.json`，写入时机（每30秒自动保存 + 应用退出时）

当前实现使用普通 dict 结构，非 dataclass。由 `ConfigService.save_session()` 写入：

```python
# 实际存储结构（session.json）
{
    "files": [
        {
            "path": str,                    # 文件绝对路径（未保存文件为空字符串）
            "cursor_pos": int,              # 光标在文档中的绝对位置
            "encoding": str,                # 编码名称，如 "utf-8"
            "content": str,                 # 文件内容（仅未保存文件或未保存修改时需要）
            "modified": bool,               # 是否有未保存修改
            "language": str,                # 语法高亮语言（可选，默认为空）
            "syntax_auto_detect": bool,     # 是否启用自动识别语法（可选，默认为 True）
        },
    ]
}
```

**注意**：`modified` 字段在 `save_session()` 写入时总是 false（标签恢复后统一标记），`language` 和 `syntax_auto_detect` 用于在会话恢复时精确还原每个标签的语法高亮状态。

**恢复策略**：session.json 损坏→放弃恢复+空会话；文件不存在→跳过+日志；未保存文件（path 为空）恢复时创建"未命名"标签；恢复的标签默认标记为未修改。

### 2.5 AppSettings

**校验**：pydantic-settings `BaseSettings` 模型，存储于 `settings.json`

```python
class AppSettings(BaseSettings):
    font_size: int = Field(default=13, ge=8, le=24)
    font_family: str = Field(default="")
    theme: str = Field(default="dark")                    # "dark" / "light" / "high_contrast"
    show_line_numbers: bool = Field(default=True)
    word_wrap: bool = Field(default=False)
    auto_indent: bool = Field(default=True)
    bracket_completion: bool = Field(default=True)
    tab_width: int = Field(default=4, ge=2, le=8)
    reduce_animation: bool = Field(default=False)
    first_run: bool = Field(default=True)                 # 首次启动标记
    
    model_config = {"extra": "allow"}                     # 允许额外字段前向兼容
```

**说明**：`recent_files` 和 `max_recent_files` **不**由 AppSettings 管理——最近文件列表通过 `FileService._add_recent_file()` 直接读写 `settings.json["recent_files"]`，由 `Settings` 底层处理。会话管理（session.json）也绕过 AppSettings，由 `ConfigService.save_session()` / `load_session()` 直接读写。

## 3. 核心数据流

### 3.1 数据流向总览

```
用户输入(键盘/鼠标/拖拽) → UI层(Qt事件捕获) → Controller(SignalBus/直接连接编排) → Service(业务逻辑) → Infrastructure(持久化) → 磁盘/文件系统
                                                                       ↓
                                                                  状态变更通知(SignalBus广播给所有订阅者)
```

### 3.2 文件打开

1. `DialogCoordinator.show_open_file_dialog()` → 用户选择路径（取消则返回）
2. `TabManager.find_tab_by_path(path)` → 已打开则切标签，流程结束
3. `FileService.get_file_size()` → >10MB 则 `DialogCoordinator.confirm_large_file()`
4. `FileService.open_file()` → `FileIO.read()` + `EncodingDetector.detect()` → 返回 `(content, encoding, line_ending, error)`
5. `TabManager.create_tab(path, content, encoding, file_size)` → 创建编辑器实例 + 语法高亮(SyntaxService映射) + 文件监听
6. `SignalBus.file_opened.emit(path)` → StatusBar 更新编码/语言信息，FileService 更新最近文件列表（去重，截断到 20 条）

### 3.3 文件保存

1. `TabManager.pause_file_watcher(path)`（防止保存时触发外部变更事件）
2. `FileService.save_file(path, content, encoding=encoding)` → `FileIO.write()` 原子写入流程：临时文件 → fsync → 重命名覆盖原文件（失败时保留原文件）
3. 写入失败：`DialogCoordinator.show_error()` → 恢复文件监听 → 流程结束（不标记已保存）
4. 写入成功：`TabManager.mark_saved(index, path)` → `meta["modified"] = False` → `SignalBus.file_saved.emit(path)` → 标签标题去掉 `*`
5. 编辑器撤销栈保持不变（可撤销到保存前状态）

### 3.4 搜索（带缓存）

1. 用户 Ctrl+F → SearchBar 弹出（如有选中文本自动填充）→ 输入触发 150ms 延迟
2. `SearchService.find_all(text, content, options)` → `needs_research()` 判断是否可返回缓存
3. 需要重新搜索：构建正则模式 → 遍历全文 → 更新 `SearchState(matches/match_count/current_index)` → 返回 `(span_list, error)`
4. 正则无效：状态栏 5 秒提示"无效的正则表达式"
5. 无匹配：状态栏 3 秒提示"未找到: 搜索词"
6. 有匹配：导航到索引 0 → `CodeEditor.update_search_highlights()` 读取 `SearchState.matches` 通过 ExtraSelections 渲染高亮
7. 匹配项蓝色半透明背景，当前匹配项金色边框（暗色主题）或浅黄边框（亮色主题）

### 3.5 标签关闭

- 未修改：`TabManager.close_tab(index)` → 停止文件监听 → 释放编辑器 → 移除标签 → `SignalBus.file_closed.emit(path)` → 焦点切换到下一个标签
- 已修改：弹出三选一 → [保存] `_save_and_close_from_action()`(保存成功 is_modified=False→关闭) → [不保存] 直接关闭 → [取消] 无操作
- 关闭最后一个文件标签：自动显示欢迎页（索引 0）

### 3.6 编码转换

1. 用户通过状态栏编码菜单或文件菜单选择目标编码 → `StatusBar.encoding_changed.emit(target_encoding)` 或 `ActionManager` 处理
2. `TabManager.change_encoding_for_tab(index, target_encoding, force=False)` 执行转换：
   1. 检查标签有效性（索引、路径存在、非只读）
   2. 如有未保存修改，先自动保存（调用 `FileService.save_file()` 以原编码写入）
   3. 暂停文件系统监听
   4. 获取编辑器全文，调用 `FileService.change_encoding(file_path, content, target_encoding, force)`
3. `FileService.change_encoding()` 核心流程：
   1. `encoding_utils.try_encode_content()` 尝试 `content.encode(target_encoding)`
   2. 成功 → `atomic_write` 以 `wb` 模式写入编码后的字节流
   3. 失败（UnicodeEncodeError）→ force=False 返回错误（含前5个无法编码的字符位置及建议）；force=True 调用 `force_encode_content()` 清除不可编码字符后写入
4. 转换成功 → `meta["encoding"] = target_encoding` 更新元数据 → 恢复文件监听 → `SignalBus.file_encoding_changed.emit(path, target_encoding)` → 状态栏更新编码显示

**编码工具层**（`encoding_utils.py`）：提供 `try_encode_content()` / `force_encode_content()` / `get_all_available_encodings()` / `get_display_name()` 等纯函数，无 Qt 依赖。编码菜单按区域分组（Unicode/简体中文/繁体中文/日文/韩文/西欧/其他），可用编码列表运行时通过 `codecs.lookup()` 校验过滤。

### 3.7 启动/退出

**启动**：crash_debug.py(可选包装) → main.py(CLI 解析 click → sys.path 插入 → QApplication → Fluent 主题 → Logger → MainWindow) → MainWindow.__init__(SignalBus→ConfigService→ThemeService→FileService→ToolService→SearchService→SyntaxHighlighterManager→UI 布局→TabManager→FocusManager→ActionManager→SplitViewManager→SearchResultPanel→MenuManager→信号连接→加载配置+主题→恢复会话(逐个打开文件标签+光标位置+语法高亮恢复+内容差异检测)) → 首次启动或空会话时显示欢迎页 → 处理 CLI 文件参数(打开文件+跳转行列)

**退出**：`MainWindow.closeEvent` 检查未保存标签（空的新文件跳过）→ 有未保存标签时弹出三选一 MessageBox（保存/不保存/取消）→ 保存时逐个保存并校验成功 → `TabManager.save_full_session()`(遍历标签→收集 path/cursor_pos/encoding/content/language/syntax_auto_detect → ConfigService.save_session()) → ConfigService.save_settings 在配置变更时已自动持久化 → Logger 刷新关闭 → event.accept()

## 4. 存储架构

```
%APPDATA%/GlassEditor/
├── settings.json     # 用户配置(分组扁平JSON，≤2层嵌套)
├── session.json      # 会话状态(open_tabs顺序=标签栏顺序)
├── shortcuts.json    # 快捷键(仅存储与默认值不同的项)
└── ...

./logs/
├── app_YYYY-MM-DD_N.log     # 应用日志(100MB或每日轮转)
├── app_YYYY-MM-DD_N.log.gz  # 轮转后 gzip 压缩
└── crash_YYYY-MM-DD.log     # 崩溃日志

内存:
├── SearchState(实例变量)     # SearchService 持有(非 dataclass)
├── TabMeta(dict)             # TabManager 通过 tabData 持有(非 dataclass)
├── Editor 实例               # CodeEditor 持有(每标签一个，分屏时另有一个)
├── UndoStack                 # 编辑器内部维护(每标签独立)
├── ConfigService._config     # ConfigService 持有(pydantic 校验后缓存)
├── Settings._cache           # Settings 持有(JSON 解析后缓存，多文件隔离)
└── Settings._dirty_files     # Settings 持有(待刷写的脏文件集合)
```

### 文件格式要点

- **settings.json**：顶层平坦结构（无分组嵌套），pydantic 校验，含 `theme`/`font_size`/`show_line_numbers` 等编辑器配置。`recent_files` 为保留键名，由 FileService 管理（非 AppSettings 模型字段）。
- **session.json**：顶层 `files` 数组，每项含 `path`/`cursor_pos`/`encoding`/`content`/`language`/`syntax_auto_detect`。`content` 字段条件填入（未保存文件始终保存内容，已保存文件仅在有未保存修改时保存内容）。`language` 和 `syntax_auto_detect` 用于会话恢复时精确还原语法高亮状态。
- **shortcuts.json**：键为 action_id，值为快捷键字符串（仅存储与默认值不同的项）。

### 数据生命周期

| 文件 | 读取时机 | 写入时机 | 恢复策略 | 保留期 |
|------|---------|---------|---------|--------|
| settings.json | 启动时 | 500ms去抖+退出 | 损坏→默认设置 | 无限期 |
| session.json | 启动时 | 30s定时器+退出 | 损坏→空会话 | 只保留最近 |
| shortcuts.json | 启动时 | 快捷键变更 | 损坏→默认键 | 无限期 |
| logs | 追加 | 实时 | - | 30天 |

## 5. 缓存策略

### 配置缓存（ConfigService + Settings）

ConfigService 内部维护 `_config` 字典缓存，`get()` 优先从缓存读取，未命中时从 settings.json 加载并缓存。

写操作（`set()`）通过 pydantic 校验后逐项调用 `Settings.set()`——Settings 底层使用 `_cache` + `_dirty_files` + `_debounce_timer`（500ms 去抖），多次快速 set() 合并为一次磁盘写入。应用退出时通过 `Settings.flush()` 跳过定时器直接刷写。

**注意**：ConfigService 不直接管理去抖或脏标记，这些由 Settings 单例统一处理。ConfigService 的职责是 pydantic 校验 + 配置键值映射。

### 搜索缓存（SearchService）

`SearchState.needs_research()` 比较新的搜索文本/选项与 `last_search_text`/`last_options`，参数未变时直接返回缓存中的 `matches` 列表，避免正则重新遍历全文的开销。

## 6. 状态管理

| 类型 | 范围 | 示例 | 通知机制 |
|------|------|------|---------|
| 全局 | 跨模块共享 | SignalBus信号、ThemeService色板、AppSettings | SignalBus广播(pyqtSignal) |
| 局部 | 模块内持有 | SearchState(SearchService)、UndoStack(Editor)、TabEntity(TabManager) | (result,error)返回值 |
| 瞬时 | 不需持久化 | 对话框开关、状态栏临时消息、动画状态 | 直接信号连接 |

**变更通知优先级**：1.SignalBus广播(文件/主题/配置变更) 2.直接信号连接(按钮点击/搜索栏变更) 3.方法返回值(Service同步调用)

**规范**：状态变更必须通过上述机制通知，禁止直接修改其他模块的属性。状态读取可以跨层（下层向上层返回值），状态写入必须遵守分层方向。

## 7. 数据安全

**路径脱敏**：`C:\Users\rikka\code\main.py` → `C:\Users\***\code\main.py`（替换 Users 后的用户名部分）

**日志脱敏**（Logger 全局过滤器）：匹配敏感字段 key 名（password/secret/token/api_key/auth/credential/private_key）→ 替换值为 `***`。另匹配信用卡号(16-19位)、身份证号(17位+数字/X)、IP 地址。

**数据保留策略**：settings.json 无限期 / session.json 只保留最近一份 / logs 30天轮转删除 / 最近文件最多20条可手动清除 / 搜索历史/剪贴板退出即清除 / 撤销栈标签关闭即清除

## 8. 事件审计

SignalBus 发射关键事件时自动记录日志：

| 事件 | 级别 | 日志模板 |
|------|------|---------|
| file_opened | INFO | "文件打开: {path}" |
| file_saved | SUCCESS | "文件保存: {path}" |
| file_closed | INFO | "文件关闭: {path}" |
| file_encoding_changed | INFO | "文件编码转换: {path} from {old_enc} to {new_enc}" |
| theme_changed | INFO | "主题切换: {theme}" |
| config_updated | DEBUG | "配置更新" |

**性能追踪点**（DEBUG 级别）：文件打开耗时 / 语法高亮耗时 / 搜索耗时+结果数 / 会话保存耗时 / 主题切换耗时

## 9. 数据一致性

**标签与编辑器一致性**：TabManager 独占地通过 `tabData()` 存储 TabEntity，禁止外部维护独立标签列表。每次操作前检查 `get_current_editor()` 非 None 和标签索引 ≥ 0。

**文件系统 vs 内存**：QFileSystemWatcher 监听打开的文件。保存前暂停监听→原子写入→恢复监听。外部修改检测：编辑器无未保存修改→自动重载；有未保存修改→用户弹窗选择。

**会话恢复一致性**：session.json 损坏→放弃恢复+空会话。文件不存在→跳过+日志。恢复的标签默认未修改。恢复后检查所有标签的文件系统状态（外部修改→提示重载，已删除→标记缺失）。
