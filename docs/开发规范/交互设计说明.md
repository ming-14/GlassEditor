# 交互设计说明 —— GlassEditor 琉璃编辑器

## 1. 交互设计哲学

### 1.1 设计原则

1. **可预测性** — 用户能预判操作结果，相同操作在不同上下文中行为一致，减少意外。
2. **高效率** — 高频操作 ≤ 2 次点击或 1 个快捷键；减少确认步骤；支持批量操作。
3. **可恢复** — 非破坏性操作支持撤销 (Ctrl+Z)；破坏性操作（批量替换、关闭未保存文件）有二次确认；会话自动保存提供崩溃恢复。
4. **可视化** — 系统状态有明确视觉反馈；操作结果即时反映；隐藏状态（编码、行尾格式）在状态栏持续可见。

### 1.2 交互成本分级

| 级别 | 最大点击 | 最大按键 | 示例 |
|------|---------|---------|------|
| Critical | 1 | 1 键 | 保存、撤销、关闭标签 |
| Frequent | 2 | 2 组合键 | 查找、新建文件、切换标签 |
| Occasional | 3 | 3 组合键 | 设置、替换、分屏 |
| Rare | 5 | 无快捷键 | 导出PDF、计算哈希、统计信息 |

## 2. 输入系统

### 2.1 快捷键架构

ActionManager 注册默认快捷键 → ShortcutRegistry 持久化存储 + 冲突检测 → QShortcut / Action.setShortcut 绑定 Qt。存储于 `%APPDATA%/GlassEditor/shortcuts.json`，冲突检测基于逆向索引表（shortcut → action_id）。

### 2.3 快捷键设计规则

键位优先级：标准约定 → Windows 平台习惯 → 单手易操作 → 避免与常用软件冲突。用户自定义可覆盖默认值，注册时 ShortcutRegistry 检测冲突并告警。Mac 兼容性（未来）：Ctrl→Cmd, Alt→Option。

### 2.4 快捷键设置界面

录制模式：用户在设置中选择快捷键项 → 进入录制模式（按钮变为"按下新快捷键..."）→ 按下组合键 → 系统检测冲突，无冲突则接受，有冲突提示"替换"或"取消"。

### 2.5 鼠标交互

**点击：** 左键单击定位光标 / 选中整行（行号区）/ 切换标签 / 触发状态栏操作（编码、行尾、语言可点击弹出菜单）；左键双击选中词；左键三击选中行；右键打开上下文菜单（编辑器/标签/行号区各有独立菜单）；中键单击标签关闭标签。光标位置标签点击后自动复制 "行: N, 列: N" 到剪贴板。

**拖拽文本：** 拖拽移动选中文本；Ctrl+拖拽复制选中文本（未来支持拖到标签栏在新标签打开）。

**拖拽标签：** 重新排序；未来支持拖出标签栏分离为独立窗口、跨窗口拖拽。

**拖拽文件：** 从文件管理器拖入 → 在标签中打开；多文件 → 依次打开；拖入已有标签 → 提示替换内容。视觉反馈：编辑器区域半透明蓝色边框，鼠标指针变化。

**滚动行为：** 垂直滚轮滚动 / Shift+滚轮水平滚动 / Ctrl+滚轮缩放字体 / Alt+滚轮逐屏。小文件（< 1MB）逐行滚动，大文件（> 1MB）3 行/步，超大文件（> 10MB）分页滚动。触摸板双指滑动平滑滚动。

## 3. 编辑器交互

### 3.1 光标与选择

**光标移动：** 方向键逐字符/行；Ctrl+方向键按词/段；Home/End 行首/行尾；Ctrl+Home/End 文件首/尾；PageUp/PageDn 翻页。光标形状：编辑模式 I 型，覆盖模式块状，只读模式箭头。

**多光标编辑：** Alt+Click 添加光标；Ctrl+Alt+↑/↓ 上/下行添加；Ctrl+D 选中当前词并添加下一匹配光标；Alt+Shift+I 在选中区域每行末尾添加光标。每光标独立输入，删除/移动同步，复制/剪切仅影响第一个光标。上限 100 个光标（AppConstant.MAX_CURSORS），超限状态栏提示。

**选择方式：** Shift+方向键逐字符/行扩展；Shift+Ctrl+方向键按词扩展；Shift+Home/End 到行首/行尾；Alt+拖拽列选择（矩形区域）；双击选词、三击选行；Shift+Click 扩展选择到点击位置。

### 3.2 自动补全与缩进

**括号自动配对：** 输入 `( [ { " '` 自动补全右括号；删除左括号自动删除配对右括号；输入右括号时跳过已有（避免重复）；选中文本后输入左括号 = 括号包裹选中文本；光标在括号上时高亮配对括号。控制开关 ConfigKey.BRACKET_COMPLETION。

**自动缩进：** Enter 换行自动缩进至上一行缩进位置；Tab/Shift+Tab 增减缩进；Ctrl+]/[ 增减选中行缩进。智能缩进：Python 冒号后自动增缩进；花括号语言 `{` 后自动增缩进；其他语言复制上一行缩进。控制开关 ConfigKey.AUTO_INDENT。

### 3.3 语法高亮

触发时机：文件加载立即应用；文本修改时局部重新高亮（仅修改行及受影响行）；语言切换时完全重新高亮。禁用条件：文件 > 5MB 降级为 PlainHighlighter、无对应词法分析器、用户手动禁用。语言检测流程：扩展名 → shebang → 纯文本 → 用户状态栏手动切换。

## 4. 搜索交互

搜索栏打开时自动聚焦到搜索输入框，如有选中文本则自动填入搜索框。输入后 150ms 自动搜索（`AppConstant.SEARCH_DELAY_MS`）。搜索选项（按钮切换）：区分大小写、全词匹配、正则表达式（无效正则表达式时状态栏提示"无效的正则表达式" 5 秒，不崩溃）。选项变更时立即重新搜索。

当前编辑器搜索：搜索栏实时显示匹配数（由 `SearchService.find_all()` 驱动）。
多文件搜索（Ctrl+Shift+F）：打开 `SearchResultPanel` 侧边栏，支持输入目录路径 + 搜索模式 + 文件通配符过滤，结果以树形结构展示（文件→行号→匹配行），点击可导航到对应位置。

F3 / Shift+F3 查找下/上一个匹配，循环导航（`SearchService.advance_next()/advance_prev()`）。

**状态转换：** 无搜索态 → Ctrl+F 激活 → 输入文本，`SearchBar` 150ms 延迟发射 → `ActionManager._on_find()` 经由 `SignalBus.search_requested` 触发 → 搜索状态由 `SearchService` 管理（有结果态 / 无结果态 / 导航态）→ Esc 或 ✕ 关闭回到无搜索态。

**替换（Ctrl+H）：** 弹出 `FindReplaceDialog`（独立对话框），包含查找输入、替换输入、选项按钮和操作按钮。单次替换当前匹配并自动定位下一个；全部替换超 `AppConstant.BATCH_REPLACE_CONFIRM_THRESHOLD`（500）处需用户确认"替换 N 处匹配项？此操作无法撤销"；替换后自动更新搜索状态。

**查找替换对话框回调流程**：`_handle_find_next_from_dialog()` → `SearchService.find_all()` → 获取匹配列表 → `navigate_to(0)` 跳转第一项。`_handle_replace()` → 当前选中替换 → 自动查找下一项。`_handle_replace_all()` → `SearchService.replace_all()` → 超过阈值确认 → `editor.setPlainText(new_content)` → `SearchService.clear()`。

## 5. 文件操作交互

### 5.1 文件打开流程

触发方式：Ctrl+O、拖拽文件、双击文件关联打开、最近文件列表点击。

流程：文件选择（返回 None 取消）→ 标签列表查重（已打开则切换）→ `FileIO.get_file_size()` 检查大小，> `AppConstant.LARGE_FILE_THRESHOLD`（10MB）弹出确认只读对话框（用户取消则中止，确认则设为只读）→ `FileService.open_file()` 自动编码检测(含 chardet) + 行尾检测 → `TabManager.create_tab()` 创建标签 + `SyntaxHighlighterManager` 应用高亮 → 若确认只读则 `editor.setReadOnly(True)` → 聚焦编辑器。

错误处理：文件不存在 → 错误提示对话框（友好标题 + 具体原因 + 建议操作）；无权限 → 错误提示；编码检测失败 → UTF-8 回退并状态栏提示"编码检测失败，已使用 UTF-8 回退"；读取部分内容 → 提示"文件过大，仅读取前 N MB"。

注：拖拽文件、最近文件列表点击、CLI 参数打开共享相同的 `TabManager.create_tab()` + `FileService.open_file()` 流程。

重新加载：`ActionManager._on_reload()` 从菜单或快捷键触发，调用 `FileService.reload_file()` 从磁盘重新读取。如有未保存更改，弹出确认对话框："文件有未保存的更改，重新加载将丢失这些更改。是否继续？"

### 5.2 文件保存流程

触发方式：Ctrl+S、Ctrl+Shift+S、Ctrl+W 关闭时提示、退出应用时提示全部未保存标签。

流程：获取编辑器内容 → 获取文件路径（无则弹出另存为对话框，取消则返回）→ 获取标签编码 `tab_manager.get_current_encoding()` → 暂停文件系统监听 → `FileService.save_file(path, content, encoding=encoding)` 原子写入（atomicwrites 库：写入临时文件 → fsync → 重命名替换原文件）→ 恢复文件监听 → `TabManager.mark_saved()` 标记已保存+`SignalBus.file_saved` 广播 → 状态栏"已保存：文件名"。写入失败弹出错误对话框，原文件不受影响，断电/崩溃时临时文件与原文件互不干扰。

### 5.3 编码转换（文件 → 编码菜单）

**入口**：菜单栏 `/文件/编码/` → 与状态栏编码点击共享同一套编码分组菜单。

**两种转换场景：**

1. **更改当前文件编码**（状态栏/菜单选择编码 → 触发转换→原子写入）：
   - 有未保存修改时先自动保存
   - 暂停文件监视 → encode + 原子写入 → 更新元数据 → 恢复监视
   - encode 失败时的交互见第 6 章编码交互

2. **强制转换**（清除不可编码字符）：
   - 在告警对话框中选择 [强制转换] → `force_encode_content()` 跳过所有无法编码的字符 → 写入文件
   - 被清除的字符数量记录日志，状态栏提示"强制编码转换，清除 N 个字符"

**限制**：文件 > 50MB 时禁用编码转换（AppConstant.ENCODING_CHANGE_MAX_FILE_SIZE），状态栏和菜单中编码项置灰并提示"文件过大，无法转换编码"。

### 5.4 关闭标签 / 退出应用

**关闭单个标签：** 无修改直接关闭；有修改弹出三选一对话框：[保存] → 保存后关闭；[不保存] → 丢弃修改关闭；[取消] → 不做操作。

**退出应用：** 遍历所有标签收集未保存项；有未保存标签则弹出对话框：[保存并退出] / [不保存并退出] / [取消]；无未保存标签直接退出。

## 6. 标签页交互

**创建：** 新建未命名标签（"未命名 1, 2, 3..."）、打开文件创建标签、欢迎页按钮点击。

**状态：** Normal（已保存）、Modified（已修改显示 "*"）、ReadOnly（只读显示 🔒）、Untitled（显示 "未命名 N"）、Welcome（欢迎页，固定在索引 0，不可关闭）。

**切换方式：** 鼠标点击标签、Ctrl+Tab / Shift+Tab 顺序/逆序切换、Ctrl+1~9 跳转指定索引标签。切换动画 150ms 淡入淡出。

**关闭：** 关闭按钮 / Ctrl+W / 中键点击；关闭后焦点移相邻标签；关闭最后文件标签后显示欢迎页。

**文件系统监听：** 检测外部修改 → 提示重新加载或忽略；检测文件删除 → 标签标记"文件缺失"（灰色显示）。

**编码交互：** 状态栏编码指示器可点击，弹出 Fluent 风格分组菜单（Unicode / 简体中文 / 繁体中文 / 日文 / 韩文 / 西欧 / 其他），当前编码打勾标记。选择新编码触发编码转换流程：

1. **有未保存修改** → 自动以原编码保存当前文件
2. **暂停文件监视** → 获取编辑器全文 → 调用 `FileService.change_encoding()` 尝试 `content.encode(target_encoding)`
3. **转换成功** → 以原子写入方式写回文件，更新标签元数据 encoding，恢复文件监视，发射 `SignalBus.file_encoding_changed`
4. **encode 失败**（含目标编码无法表示的字符）→ 弹出告警对话框，显示前 5 个无法编码的字符（位置 + Unicode 码点）及建议（"使用 GB18030 等更宽编码，或修改文本内容"），提供 [强制转换]（清除不可编码字符）和 [取消] 两个选项

**编码菜单交互细节**：编码按区域分组，每组为嵌套子菜单；可用编码列表运行时通过 `codecs.lookup()` 校验过滤，不可用的编码（如当前 Python 环境未安装对应编解码器）不显示。状态栏显示缩写（通过 `encoding_utils.get_status_bar_encoding()` 转换，如 "UTF-8-BOM" 代替 "UTF-8 with BOM"）。未保存文件或无文件标签时编码菜单项置灰并提示"保存文件后才能更改编码"。

## 7. 分屏交互

**创建分屏：** Ctrl+Alt+V 垂直分屏（水平分割编辑器区）；Ctrl+Alt+H 水平分屏（垂直分割编辑器区）。

**导航与调整：** 点击分屏区域切换焦点，焦点分屏有加粗边框指示；快捷键操作作用于焦点分屏。拖拽分隔条调整比例，比例在会话间持久化。

**关闭分屏：** 拖拽分隔条到边缘自动关闭；右键标签"关闭分屏"；全部分屏关闭后回到单屏模式。

**同一文件多分屏：** 自动复制内容到新分屏；每分屏独立光标位置；一处修改实时同步到其他分屏；共享修改标记（任一修改均标记未保存）。

## 8. 拖放交互

**文件拖入：** 从资源管理器拖入 → 标签中打开；多文件依次打开；拖入已打开标签 → 提示替换。视觉反馈：编辑器半透明蓝色边框、鼠标指针图标变化、多文件数量气泡。

**文本拖出（未来）：** 选中文本拖到资源管理器保存为文件；拖到其他应用粘贴内容。

## 9. 反馈系统

### 9.1 反馈层级

| 层级 | 延迟 | 内容 |
|------|------|------|
| L1 即时 | < 50ms | 按钮悬停/按下、光标实时更新、输入字符显示、选中背景色变化 |
| L2 操作 | < 200ms | 状态栏消息、搜索高亮更新、标签 "*" 标记切换、缩放重置 |
| L3 确认 | 用户触发 | 保存确认、批量操作确认、错误提示、信息提示对话框 |
| L4 背景 | 持续显示 | 状态栏编码/行尾/语言/缩放、标签标记、只读标记 |

### 9.2 状态栏消息

所有状态栏消息统一使用 `AppConstant.STATUS_MESSAGE_DURATION_MS`（3000ms）作为默认显示时长。特殊场景可覆盖：无效正则表达式 5000ms、批量替换完成 5000ms。管理规则：新消息覆盖旧消息；相同内容不重复。

### 9.3 错误反馈

格式：友好标题 + 具体原因 + 建议操作。分级：信息（仅状态栏）→ 警告（对话框 + 状态栏）→ 错误（对话框 + 状态栏 + 日志）→ 崩溃（崩溃对话框 + 日志文件）。

## 11. 设置交互

Pivot 三标签导航：**[通用]** **[编辑器]** **[快捷键]**

**通用标签：** 启动时恢复上次会话 / 启动时显示欢迎页；主题切换 / 减少动画 / 界面语言；最近文件最大数 / 自动保存会话 / 自动保存间隔。

**快捷键标签：** 操作-快捷键对应列表，每项可点击进入录制模式修改；底部 [恢复默认] 按钮。打开快捷键：Ctrl+,。

生效策略：实时生效（字体、主题、行号、自动换行等）；关闭对话框时统一写入 settings.json（写去抖 500ms）。恢复默认分标签恢复，快捷键恢复需确认对话框。

## 12. 进度与等待

**大文件打开：** > 10MB 显示进度对话框，含进度条和取消按钮；后台线程分段读取，不阻塞 UI；可取消操作，取消后不创建标签。

**多文件搜索：** 搜索中状态栏显示"正在搜索..."；搜索结果逐步展示（边搜边显示），无需等待全部完成；搜索完成后状态栏显示"搜索完成：找到 N 个结果"。

**哈希计算：** 大文件计算时显示进度条；后台线程计算，对话框保持响应；计算完成后显示结果并可复制。

**空状态：**
- **编辑器空状态（欢迎页）：** 居中卡片布局，包含标题"欢迎使用琉璃编辑器"、副标题"轻量级桌面文本/代码编辑器"、快捷键速查表（文件/编辑/查找/视图分组）、主题切换按钮组（深色/浅色）和 [新建文件] [打开文件] 两个操作按钮。
- **搜索空状态：** 搜索栏内显示"未找到匹配"，状态栏显示"未找到：搜索词"。
- **最近文件空状态：** 显示"暂无最近文件"，提示用户新建或打开文件。

## 13. 辅助交互

### 13.1 撤销/重做

每个编辑器独立维护撤销栈，Ctrl+Z/Y 操作，不限容量（受限于内存）。文件保存不清空撤销栈。不可撤销操作（需确认）：全部替换超 500 处、文件重载。

### 13.2 工具函数

**行操作：** 复制行 / 剪切行 / 删除行 / 移动行(Alt+↑↓) / 复制行(Alt+Shift+↑↓) / 插入空行(Ctrl+Shift+Enter / Ctrl+Enter)。

**文本工具：** 大小写转换（大写/小写/首字母大写）、排序行（升序/降序）、移除重复行、统计信息、计算哈希。以上均支持撤销。

## 14. 交互规范一致性检查

### 14.1 审查清单

- 每个操作是否有明确反馈？
- 错误消息是否包含原因和建议？
- 破坏性操作是否有二次确认？
- 高频操作是否可通过快捷键完成？
- 所有功能是否可通过键盘操作？
- 选择文本后右键菜单是否包含相关操作？
- 操作后光标位置是否合理？
- 拖放是否有视觉反馈？
- 长时间操作是否有进度指示？
- 编码、行尾、语言变更是否在状态栏即时反映？
- 相同操作在不同上下文是否一致？
- 是否有清晰的空状态指导用户操作？

### 14.2 变更流程

新增交互方式须在本文档注册；修改快捷键须更新第 2 节；新增对话框须注册；新增自定义组件须在 UI 设计规范注册；所有交互变更须经可用性评审。
